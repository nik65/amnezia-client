# Автоматический переход на AWG 3.1

Начиная с 5.0.3.6 приложение администратора самостоятельно проверяет сохранённые
self-hosted серверы при запуске и после успешного поиска установленных протоколов.
Вводить адрес, UDP-порт, digest образа или номер поколения больше не требуется.
Нужны уже сохранённые административные SSH-реквизиты и fingerprint сервера.
Импортированный пользовательский профиль не даёт права устанавливать серверные
компоненты, но совместимый клиент получает предложение миграции автоматически.

Проверка и подготовка идут последовательно в фоне. В настройках AWG отображается
состояние проверки, готовность либо понятная причина ожидания. Временный сбой
связи, загрузки зависимостей или занятый порт повторно проверяется автоматически
через 30, 120, 300 секунд, далее не чаще одного раза в 15 минут. Перезапускать
приложение не требуется. Ошибки авторизации, fingerprint, целостности образа,
совместимости и журнала автоматически не повторяются. Удалённый или изменённый
административный профиль отменяет ожидающую попытку.

Приложение использует существующий адрес VPN из клиентского профиля, а при его
отсутствии — адрес сохранённого административного сервера. Поддерживаются hostname
и IPv4. Свободный UDP-порт выбирается по серверным сокетам и публикациям Docker,
повторно проверяется перед созданием контейнера. Первое автоматическое поколение
равно 1; готовое поколение с тем же образом, адресом и исходной конфигурацией
повторно используется. Изменившаяся готовая миграция требует проверки и не
перезаписывается автоматически.

Для Linux x64 применяется встроенный проверенный официальный образ
`amneziavpn/amneziawg-go` выпуска `3.1.20260814`, закреплённый digest манифеста.
Проверяются архитектура, immutable ID, SHA256 бинарного файла и необходимые
утилиты. Строка `--version` этого upstream-образа устарела; идентичность подтверждают
закреплённые байты, а поддержку протокола — фактическое принятие параметров AWG 3.1
созданным endpoint. Иные архитектуры автоматически не подменяются.

Подготовка создаёт параллельный VPN endpoint и служебные контейнеры. Исходный VPN
контейнер остаётся работающим. Совместимый клиент получает подписанное предложение
через существующий туннель, сохраняет его и проверяет новый endpoint при следующем
подключении. Прежние клиенты продолжают использовать прежний endpoint. Состояние
«готов» означает готовность сервера, а не доказательство перехода всех клиентов.

Разработка и сборка не запускают подготовку на production. Приёмка выполняется
только в проверенных Windows/Linux release-lab guests. Android sandbox отключён;
приёмка Android ожидает реального смартфона.
